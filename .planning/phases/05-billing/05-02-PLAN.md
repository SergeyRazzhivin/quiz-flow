<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client → create-payment | Owner requests a payment; user identity must be JWT-verified, not body-supplied |
| YooKassa servers → yookassa-webhook (public) | Untrusted external POST; no HMAC signature available |
| owner client → ai-generate-quiz | Owner triggers AI generation; monthly limit must be enforced server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06 | Spoofing | Forged payment.succeeded POST to webhook | mitigate | IP allowlist CIDR check against YooKassa published ranges; unknown IP → 200 no-op |
| T-05-07 | Spoofing/Replay | Duplicate webhook with valid payment_id | mitigate | idempotency SELECT on `yookassa_payment_id` before upsert |
| T-05-08 | Tampering | Client sets metadata.user_id to another user | mitigate | create-payment sets metadata.user_id from JWT `user.id`, never request body |
| T-05-09 | Tampering | Concurrent AI requests bypass the monthly limit | mitigate | insert-then-count gate; over-limit row deleted, 429 returned (Pitfall 4) |
| T-05-10 | Information Disclosure | YooKassa secret_key in client bundle | mitigate | secret only in Edge Function env; create-payment is server-side |
| T-05-11 | Tampering | Free user resolved as Pro via stale profiles.plan | mitigate | AI gate resolves plan via `get_effective_plan` RPC (subscriptions only) |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | no new packages this phase (RESEARCH Package Legitimacy Audit: none) |
</threat_model>
