Attach `CREATE TRIGGER enforce_quiz_limit BEFORE INSERT ON quizzes FOR EACH ROW EXECUTE FUNCTION check_quiz_limit()`.
    Create `check_question_limit()` analogously: resolve owner via `SELECT owner_id FROM quizzes WHERE id = NEW.quiz_id`, call `get_effective_plan(v_owner)`; if 'pro' RETURN NEW; else `COUNT(*)` questions WHERE `quiz_id = NEW.quiz_id`; if count >= 10 `RAISE EXCEPTION 'QUESTION_LIMIT_EXCEEDED: ...'`. NOTE: `subscriptions` (migration 006) has no `created_at` column — add `ALTER TABLE subscriptions ADD COLUMN IF NOT EXISTS created_at timestamptz NOT NULL DEFAULT now()` in this migration before this function. Compute rolling-30-day window start: `anchor + FLOOR(EXTRACT(EPOCH FROM (now() - anchor)) / (30*86400)) * INTERVAL '30 days'` (D-12).

Free AI limit = 10, Pro = 30 per D-14.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client → Postgres | Owner client INSERTs into quizzes/questions; must not bypass plan limits |
| anon client → Postgres | Anon must never read subscriptions or ai_generations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | Direct client INSERT on quizzes | mitigate | BEFORE INSERT trigger `check_quiz_limit` with SECURITY DEFINER blocks 4th quiz |
| T-05-02 | Tampering | Direct client INSERT on questions | mitigate | BEFORE INSERT trigger `check_question_limit` blocks 11th question |
| T-05-03 | Elevation of Privilege | Trigger function reading subscriptions | mitigate | trigger functions are SECURITY DEFINER + `SET search_path = public` (Pitfall 3) |
| T-05-04 | Information Disclosure | anon reading ai_generations | mitigate | RLS enabled, owner-only policy, no anon policy at all |
| T-05-05 | Tampering | stale `profiles.plan` used for enforcement | mitigate | enforcement delegates only to `get_effective_plan()` reading subscriptions (D-06) |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | no new packages this phase (RESEARCH Package Legitimacy Audit: none) |
</threat_model>
