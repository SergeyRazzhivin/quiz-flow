## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser client → Supabase PostgREST | Question and answer-option CRUD; RLS enforces owner-of-parent-quiz scope |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Elevation of Privilege | Question / answer-option CRUD | mitigate | RLS `owner_manage_questions` / `owner_manage_answer_options` (Plan 01 migration 007) enforce ownership via the parent quiz's `owner_id` — a user cannot modify questions of another user's quiz |
| T-04-02 | Information Disclosure | `answer_options.is_correct` reaching guests | mitigate | Anon reads go through the `answer_options_public` view (Plan 01) which excludes `is_correct`; the editor uses the authenticated `answer_options` table — correct answers never leak to anon |
| T-04-03 | Tampering | `order_index` corruption via concurrent reorder | mitigate | `reorderQuestions` batch-upserts ALL questions atomically; no `UNIQUE` constraint blocks transient duplicates (PITFALLS §6.4) |
| T-04-04 | Repudiation / data loss | Delete question | mitigate | Confirmation `Dialog` (D-11) required before `DELETE`; `ON DELETE CASCADE` cleanly removes child answer_options |
| T-04-05 | Tampering | Publishing an invalid/empty quiz | mitigate | `validateForPublish` blocks publish unless every question has ≥2 options with ≥1 correct (D-13); enforced in the store before the `is_published` UPDATE |
</threat_model>
