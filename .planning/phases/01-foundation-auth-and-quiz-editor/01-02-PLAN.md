<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser client → Supabase PostgREST | Quiz list reads/writes; RLS enforces owner vs. published scoping |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | `/` published list | mitigate | `fetchPublishedQuizzes` relies on the `anon_read_published_quizzes` RLS policy (Plan 01) — only `is_published=true` rows return |
| T-02-02 | Elevation of Privilege | `deleteQuiz` from `/my` | mitigate | RLS `owner_manage_quizzes` policy enforces `owner_id = (SELECT auth.uid())` — a user cannot delete another user's quiz even by passing an arbitrary id |
| T-02-03 | Tampering | `createQuiz` owner_id | mitigate | `createQuiz` sets `owner_id` from `supabase.auth.getUser()` server-validated session, not client input |
| T-02-04 | Repudiation / accidental data loss | Delete quiz | mitigate | Confirmation `Dialog` (D-07) requires explicit "Удалить" before the `DELETE` executes |
| T-02-05 | Spoofing | `/my` access while logged out | accept | Router guard from Plan 01 already redirects; no additional control needed in this plan |
</threat_model>
