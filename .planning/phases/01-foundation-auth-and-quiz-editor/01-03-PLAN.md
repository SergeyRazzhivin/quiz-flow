<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser client → Supabase Storage | Cover image file uploads cross here; Storage INSERT policy enforces path ownership |
| Browser client → Supabase PostgREST | Quiz metadata + publish state updates; RLS enforces owner scope |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | Cover upload path | mitigate | Upload path is `covers/{ownerId}/{quizId}/{uuid}.{ext}`; the Storage INSERT policy (Plan 01 migration 007) requires the first folder segment to equal `(SELECT auth.uid())` — a user cannot write into another user's directory |
| T-03-02 | Tampering | Quiz metadata / `is_published` update | mitigate | `updateQuiz` goes through RLS `owner_manage_quizzes`; only the owner can modify their quiz |
| T-03-03 | Denial of Service | Oversized image upload | mitigate | Client-side 5MB size check and `resizeImageToMaxWidth` to 1280px cap upload payload size (D-17) |
| T-03-04 | Tampering | Malicious file disguised as image | mitigate | MIME type allowlist (jpeg/png/webp); `resizeImageToMaxWidth` re-encodes through canvas, discarding non-image payloads |
| T-03-05 | Information Disclosure | Public `covers` bucket | accept | Bucket is intentionally public — cover images are shown to anon users on `/`; no sensitive data in covers (RESEARCH.md Open Question 4) |
</threat_model>
