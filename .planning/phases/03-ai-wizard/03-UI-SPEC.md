# Phase 3 — UI Design Contract

> Visual and interaction contract for the AI Wizard. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> The wizard reuses the design system established in Phases 1–2 — it invents nothing new. All values below are detected from the existing codebase (`src/6-shared/ui/`, `src/1-app/styles/main.css`, `src/4-features/quiz-editor/`) and confirmed against `03-CONTEXT.md` locked decisions D-01..D-12.

## Spacing Scale

Declared values (multiples of 4 — matches the editor's existing rhythm: `mt-2`/`mt-4`/`gap-2`/`gap-3`/`px-6`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside buttons (`gap-2` = 8px is the button default; 4px for tight inline) |
| sm | 8px | Compact element spacing — label-to-field, `gap-2` chip rows |
| md | 16px | Default vertical rhythm between fields within a step (`space-y-4`) |
| lg | 24px | Step content block padding; gap between the stepper and the step body (`px-6` / `py-6`) |
| xl | 32px | Wizard card internal padding on desktop; gap between step body and the footer nav |
| 2xl | 48px | Vertical centering offset for step 4 spinner block |
| 3xl | 64px | Top/bottom breathing room of the full-screen wizard shell |

Exceptions:
- Difficulty-level segmented control and the file-drop zone reuse the editor's drop-zone height `h-48` (192px) for the file tab — a deliberate match to `CoverUpload.vue`, not a new token.
- Component heights are fixed by the design system: inputs/buttons `h-9` (36px), `sm` buttons `h-8` (32px), `lg` buttons `h-10` (40px). These are component contracts, not spacing tokens.

## Typography

Three roles + display — matches the editor (`text-2xl font-semibold` titles, `text-sm` body, `text-base` empty-state). Exactly two weights: `400` regular and `600` semibold.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (`font-normal`) | 1.5 |
| Label | 14px (`text-sm`) | 600 (`font-semibold`) — field labels and tab-trigger text; uses semibold (not medium) so the wizard's type contract stays at exactly two weights | 1.4 |
| Heading | 20px (`text-xl`) | 600 (`font-semibold`) | 1.3 — step titles ("Шаг 1. Название теста") |
| Display | 24px (`text-2xl`) | 600 (`font-semibold`) | 1.2 — the wizard's top-level title and the step-4 status headline |

The shared `Button.vue` and `TabsTrigger.vue` components carry their own `font-medium` (500) internally; the wizard reuses them verbatim and does not restyle them. That 500 weight is a pre-existing design-system property of those components, not a weight the wizard introduces — the wizard's own type contract above declares exactly two weights (`400` + `600`).

Helper text and validation messages: 12px (`text-xs`), weight 400, color `neutral-500` (helper) / `red-400` (error). Mirrors `Button` `sm` (`text-xs`) and the editor's helper labels.

## Color

The wizard is dark-only. The 60/30/10 split below describes the wizard surfaces; values are the exact neutrals already used across the editor and `6-shared/ui`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a0a` (`neutral-950` / app bg) | Full-screen wizard shell background |
| Secondary (30%) | `#171717` (`neutral-900`) — cards `#101010` for inset textarea | Wizard card surface, input fields (`bg-neutral-900`), the step-4 spinner card |
| Accent (10%) | `#f97316` (`orange-500`, hover `orange-600`) | See reserved-for list below |
| Destructive | `#ef4444` (`red-500`, hover `red-600`) | Not used as an action in this phase — see note |

**Accent reserved for (explicit list — never "all interactive elements"):**
1. The primary wizard navigation button — "Далее" / "Сгенерировать" (`Button variant="default"`).
2. The current/completed step marker in `WizardStepper` (active dot/number fill + connector).
3. The active tab indicator on the step-2 text⇄file `TabsTrigger` (focus ring `ring-orange-500`).
4. Input/textarea focus rings (`focus-visible:ring-orange-500`) — design-system default, inherited.
5. The file-drop zone active drag state (`border-orange-500 bg-orange-500/15`) — matches `CoverUpload.vue`.
6. The step-4 stage spinner (`Loader2` icon tinted `text-orange-500`).
7. The "Повторить" retry button after a failed generation (`Button variant="default"`).

Everything else stays neutral: secondary nav button "Назад" uses `variant="outline"`; the close/exit affordance uses `variant="ghost"`.

**Destructive note:** Phase 3 has **no destructive action** — D-03 means an abandoned wizard deletes nothing (no `quizzes` row is ever created). The D-12 "leave step 4" confirmation is a *caution*, not a destructive delete: its confirm button uses `variant="default"` (orange) labelled "Покинуть", its cancel uses `variant="outline"`. `red-500` is therefore not used in this phase except for inline validation message text (`text-red-400`).

## Layout & Interaction Contract

> These resolve the layout questions `03-CONTEXT.md` left to Claude's discretion ("visual styling within the established design system"). They are prescriptive — the executor implements them as written.

**Wizard shell (D-01 — dedicated full-screen route `/ai-wizard`):**
- Full-viewport `100dvh` (never `100vh` — project constraint, matches the editor). Background `#0a0a0a`.
- A centered content column, `max-w-2xl` (672px), `mx-auto`, horizontal padding `px-6`.
- Vertical structure: top stepper bar → step body (grows, scrolls if needed) → fixed footer nav. Same `auto 1fr auto` grid discipline as the editor (`QuizEditorWidget`).
- Top-left: a `ghost` icon button (`X` icon) to exit the wizard back to `/my`; on steps 1–3 it exits immediately, on step 4 it triggers the D-12 confirmation.

**Stepper (`WizardStepper.vue`):**
- Horizontal row of 4 numbered markers connected by a thin line, full content width, placed directly under the page title.
- Marker states: completed = filled `orange-500` circle with a `Check` icon; current = filled `orange-500` circle with the step number; upcoming = `neutral-800` circle with `neutral-500` number. Connector segment between two completed steps is `orange-500`, otherwise `neutral-800`.
- Each marker has its compact label (`Название` / `Материал` / `Параметры` / `Генерация`) below it, `text-xs`, `neutral-500` (upcoming/completed) / `neutral-50` (current).
- Steps are **not** clickable to jump forward; back-navigation is via the footer "Назад" button only.

**Footer navigation:**
- Right-aligned button group. Primary "Далее"/"Сгенерировать" (`default`), secondary "Назад" (`outline`, hidden on step 1).
- "Далее"/"Сгенерировать" is `disabled` until the current step is valid (standard wizard behaviour — `03-CONTEXT.md` Claude's discretion). Disabled buttons use the design system's `disabled:opacity-50`.
- Step 4 has **no footer nav** — the owner cannot advance or go back (D-12); the only controls present appear on failure (Повторить / Изменить параметры).

**Step 2 arrangement (D-04 + D-05):**
- A `Tabs` block at the top: `TabsList` with two `TabsTrigger`s ("Вставить текст" / "Загрузить файл"), then the matching `TabsContent`.
  - Text tab: a full-width `textarea`, ~10 rows, styled like the editor description field (`rounded-2xl border-neutral-800 bg-[#101010]`, orange focus ring).
  - File tab: a drop zone reusing the `CoverUpload.vue` visual exactly — `h-48`, `border-2 border-dashed`, `ImagePlus`→use `FileUp` icon, idle/drag-over/loading states. On file chosen: show filename + size + a ghost "Убрать файл" button.
- Below the tabs, always visible regardless of tab: the **clarifying-prompt** field — a `textarea` (~3 rows), with its own label and helper. It is one shared field across both tabs (D-05).

**Step 3 arrangement (D-07 + D-08):**
- Question-count: a numeric `Input` (`type="number"`, `h-9`, `w-24`), label above, helper below — same pattern as the editor's time-limit field.
- Difficulty: a 3-segment control built from `TabsList`/`TabsTrigger` styling (single-select, full width, three equal segments — "Лёгкий"/"Средний"/"Сложный"); active segment uses the `data-[state=active]` neutral fill the design system already defines, no extra orange fill needed.
- Difficulty-prompt: an optional single-line `Input` or 2-row `textarea`, clearly marked "(необязательно)".

**Step 4 arrangement (D-10):**
- The step body is a vertically + horizontally centered card (`bg-neutral-900`, `rounded-2xl`, `p-8`).
- A spinning `Loader2` icon (`h-8 w-8`, `animate-spin`, `text-orange-500`) — identical mechanic to `CoverUpload.vue`'s loading state.
- Below it: the current stage status line (display 24px / `text-2xl` semibold) which updates live as `ai_jobs.stage` advances, then the subtitle (`text-sm neutral-400`), then the privacy small-print (`text-xs neutral-600`).
- On failure: the spinner is replaced by an `AlertTriangle` icon (`text-red-400`), the error heading + body, and the two recovery buttons.
- No percentage bar, no `ProgressBar.vue`, no fake progress animation (D-10).

**Loading / disabled feedback:** consistent with the app — `toast.error` for unexpected network failures (the established `vue-sonner` pattern, `D-12` Phase 1). The step-4 failure state is in-page (not a toast) because it carries a recovery action.
