<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Guest browser -> start-quiz-session EF | Untrusted guestToken crosses here; verified before any DB write |
| sessionStorage <-> guest browser | guestToken stored client-side; opaque to the client, only the EF can verify it |
| Public /q/:token route | No auth guard — anyone with the URL reaches the page; credential check is the gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-12 | Spoofing | forged guestToken in start-quiz-session call | mitigate | verifyGuestToken (jose, HS256) rejects bad signatures and expired tokens; 401 before any DB access |
| T-02-13 | Tampering | double-click / re-mount creates duplicate sessions | mitigate | isStarting store guard + start-quiz-session resume branch + migration 009 partial unique index on quiz_sessions(quiz_access_id) WHERE finished_at IS NULL |
| T-02-14 | Spoofing | forged sessionId injected by the client | mitigate | start-quiz-session derives the session from the token's quiz_access_id, never trusts a client-supplied sessionId |
| T-02-15 | Information Disclosure | guest token stolen and replayed | accept | 1h JWT TTL bounds the window; sessionStorage clears on tab close; quiz-taking is low-value data — short TTL is the proportionate control |
| T-02-16 | Denial of Service | guest token replay after expiry | mitigate | jwtVerify enforces the exp claim automatically; expired token -> 401 -> store routes to 'invalid'/session-expired graceful state |
</threat_model>
