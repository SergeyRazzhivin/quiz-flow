D-17 partial-credit formula (RESEARCH Pattern 6): per question score =
  max(0, (correctSelected - incorrectSelected) / totalCorrectOptions); totalCorrect 0 -> 0.
  Quiz total = sum of per-question fractions (0..N). Percentage = round(total / N * 100).

get-quiz-result request: { guestToken, sessionId? }   response: { score, totalQuestions, percentage, label }

  finished + single-attempt (allow_retake false) -> show result; finished + allow_retake true -> offer new attempt.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Guest browser -> submit-quiz-answers EF | Untrusted guestToken + sessionId; the client never sends a score |
| submit-quiz-answers EF -> answer_options base table (service_role) | The only place is_correct is read; must never echo it to the client |
| get-quiz-result EF -> guest browser | Result payload must contain only score/percentage/label |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-22 | Tampering | client submits a forged score | mitigate | submit-quiz-answers ignores any client score; it computes the score server-side from session_answers + answer_options.is_correct |
| T-02-23 | Information Disclosure | is_correct leaks via the submit/result response | mitigate | is_correct is read only inside scoring; submit and get-quiz-result responses contain only score/totalQuestions/percentage/label; grep gate in Task 1 verify checks the surface |
| T-02-24 | Spoofing | forged guestToken / sessionId on submit or result retrieval | mitigate | verifyGuestToken first; then confirm the session's quiz_access_id matches the token payload before scoring or returning a result |
| T-02-25 | Tampering | double submission (timer expiry racing manual stop) inflates/changes the score | mitigate | store-level isSubmitting guard + submit-quiz-answers idempotency: an already-finished session returns its stored score without re-scoring |
| T-02-26 | Repudiation | a taker disputes their recorded score | accept | finished_at + score are server-set and immutable from the client; per-attempt rows are retained — sufficient for v1, no audit log needed |
</threat_model>
