  <action>
    Create `supabase/functions/create-quiz-access/index.ts` — an owner-authenticated Edge Function. Because it has NO `config.toml` block (per 02-01 Task 2), Supabase enforces `verify_jwt = true` automatically, so the request always carries a valid owner JWT. The handler must:
    1. Handle OPTIONS with `corsHeaders`.
    2. Parse `{ quizId, label, expiresAt }` from the body.
    3. Create a service_role client; resolve the calling user via `supabase.auth.getUser(<bearer token from Authorization header>)`.
    4. Verify ownership: SELECT the quiz and confirm `owner_id === user.id`. On mismatch return HTTP 403.
    5. Generate credentials with cryptographically secure randomness (RESEARCH "Don't Hand-Roll" — never `Math.random()`): `login` = 8-char string, `password` = 16-char string, both from `crypto.getRandomValues` over a safe alphabet. The owner sets only the `label`; login and password are auto-generated (D-14). `token` may be omitted from the INSERT (the column DEFAULTs to `gen_random_uuid()`); capture it in the `INSERT ... returning` clause.
    6. `passwordHash = await bcrypt.hash(password, 10)` — import `bcrypt from 'npm:bcryptjs@2'`. If 02-01's bcrypt probe required the PBKDF2 fallback, use the same fallback helper here.
    7. INSERT into `quiz_access` (`quiz_id`, `login`, `password_hash`, `label`, `expires_at`) returning `token`.
    8. Return HTTP 200 `{ token, login, password }` — plaintext password ONCE; never stored, never re-returned (D-15).
    Create `src/5-entities/quiz-access/model.ts` — the `QuizAccess` interface per the PATTERNS analog (NO `password_hash` field).
    Create `src/5-entities/quiz-access/api.ts` following the `answer-option/api.ts` analog: `fetchAccessLinks(quizId)` selecting `id, quiz_id, token, login, label, expires_at` (never `password_hash`) ordered by `created_at` desc, and `deleteAccessLink(id)` — both via the authenticated `supabase` client (RLS `owner_manage_quiz_access` covers them; no EF needed for delete per RESEARCH Assumption A4).
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Owner browser -> create-quiz-access EF | Authenticated owner crosses here; EF must still confirm quiz ownership |
| create-quiz-access EF -> Postgres (service_role) | service_role bypasses RLS — ownership check is the EF's responsibility |
| Owner browser -> quiz_access (direct delete/select) | RLS `owner_manage_quiz_access` enforces per-owner scope |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Elevation of Privilege | non-owner calls create-quiz-access for another owner's quiz | mitigate | EF resolves the caller via supabase.auth.getUser and verifies quiz.owner_id === user.id; returns 403 on mismatch; verify_jwt=true rejects unauthenticated calls |
| T-02-08 | Elevation of Privilege | owner deletes/reads another owner's access links | mitigate | fetchAccessLinks/deleteAccessLink use the authenticated client; existing RLS owner_manage_quiz_access scopes rows by owner_id |
| T-02-09 | Information Disclosure | password_hash reaches the owner client | mitigate | quiz-access/model.ts has no password_hash field; fetchAccessLinks select list omits it; grep gate in Task 1 verify asserts this |
| T-02-10 | Information Disclosure | weak/guessable generated credentials | mitigate | login/password generated via crypto.getRandomValues, not Math.random; token is UUID v4 from the DB default |
| T-02-11 | Repudiation | plaintext password recoverable after creation | accept | Only password_hash is stored; plaintext shown once at creation by design (D-15) — irreversible by intent, not a defect |
| T-02-SC | Tampering | npm/Deno package supply chain (bcryptjs, supabase-js) | mitigate | supabase-js [VERIFIED]; bcryptjs verified by 02-01's _probe-bcrypt checkpoint before this plan's EF ships |
</threat_model>
