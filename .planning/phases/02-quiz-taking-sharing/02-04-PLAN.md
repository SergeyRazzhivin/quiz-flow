<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Guest browser -> upsert-session-answer EF | Untrusted guestToken + sessionId + answer payload crosses here |
| Client clock -> timer | The browser clock is untrusted; only the server started_at anchors the countdown |
| upsert-session-answer EF -> session_answers (service_role) | service_role bypasses RLS — the EF must confirm session ownership |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-17 | Spoofing | forged guestToken / sessionId in upsert-session-answer | mitigate | verifyGuestToken first; then confirm the session's quiz_access_id matches the token payload before any write |
| T-02-18 | Tampering | client clock manipulation to extend the timer | mitigate | timeRemainingSeconds is computed from the server started_at + time_limit_sec; the client clock only affects display; 02-05's submit recomputes finished_at server-side |
| T-02-19 | Tampering | answer loss / answers withheld until submit | mitigate | selectAnswer upserts each answer immediately via the EF; onConflict (session_id,question_id) makes re-selection idempotent |
| T-02-20 | Tampering | guest writes directly to session_answers bypassing the EF | mitigate | session_answers has no anon RLS policy — direct anon writes are rejected; all writes route through the service_role EF |
| T-02-21 | Information Disclosure | is_correct inferred during answering | accept | questions/options were delivered via answer_options_public in 02-01 with no is_correct; no scoring data is sent until submit — no additional control needed here |
</threat_model>
