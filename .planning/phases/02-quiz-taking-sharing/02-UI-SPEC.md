# Phase 2 — UI Design Contract

> Visual and interaction contract for Phase 2: Quiz Taking & Sharing.
> Generated by gsd-ui-researcher. Covers requirements TAKE-01–10, SHARE-01–03, EXT-04.
> This spec EXTENDS the Phase 1 design system — it does not re-invent it.

---

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | hand-crafted shadcn-vue-style (no CLI) | Phase 1 established — components in `src/6-shared/ui/` |
| Preset | none — components added individually | Phase 1 carry-forward |
| Component library | radix-vue (underlying primitives) | Phase 1 carry-forward |
| Icon library | lucide-vue-next | Phase 1 carry-forward |
| Font | Inter (Google Fonts, loaded via `<link>` in `index.html`) | Phase 1 carry-forward |
| CSS framework | Tailwind CSS v4 | CLAUDE.md |
| Toast library | vue-sonner (dark theme, top-right, `rounded-2xl`) | Phase 1 carry-forward |

**Theme:** Dark-first. Page background `#0a0a0a`. No light mode toggle in Phase 2.

**Palette correction vs 01-UI-SPEC.md:** Phase 1 shipped violet/indigo — the implementation pivoted mid-phase to orange accent + neutral-900 surfaces. Phase 2 uses the IMPLEMENTED palette, not the spec'd one. All orange references below are `orange-500` (`#f97316`).

**Components reused from Phase 1 without modification:**
- `Button.vue` — variant: default (orange), destructive, outline, secondary, ghost, link
- `Input.vue` — `border-neutral-700 bg-neutral-900 focus:ring-orange-500`
- `Dialog.vue` / `DialogRoot` (radix-vue) — used for stop-confirmation, access-link modal
- `Switch.vue` (PrimeVue ToggleSwitch wrapper)
- `Tooltip.vue`

**New components for Phase 2** (create in `src/6-shared/ui/` or feature-local):
- `ProgressBar.vue` — animated horizontal bar, orange fill on neutral-800 track
- `TimerDisplay.vue` — monospace countdown, turns red at ≤20% remaining

## Spacing Scale

Inherited from Phase 1. No changes.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, tight inline gaps |
| sm | 8px | Compact element spacing, button icon gap, answer row internal gap |
| md | 16px | Default element spacing, card padding, form field gap |
| lg | 24px | Section padding, quiz-taking body padding |
| xl | 32px | Layout gaps, screen-level section breaks |
| 2xl | 48px | Major section breaks, result page vertical spacing |
| 3xl | 64px | Page-level vertical centering offset |

**Phase 2 exceptions:**
- Answer option touch target on mobile: minimum 44px hit area. Visual height may remain auto; `min-h-[44px]` on the row container.
- Timer badge: `px-3 py-1` (12px / 4px) — tight inline pill, not standard spacing token.
- Progress bar height: 4px fixed (`h-1`) — below token scale, intentional.
- Sticky header height: 56px (`h-14`) — matches AppHeader height from Phase 1.

## Typography

Inherited from Phase 1. Exactly 2 weights: 400 and 600.

| Role | Size | Weight | Line Height | Phase 2 Usage |
|------|------|--------|-------------|---------------|
| Body | 14px | 400 (regular) | 1.5 | Answer option text, helper text, meta info, credentials copy, link list rows |
| Label | 16px | 400 (regular) | 1.5 | Form labels, question text, result page body, intro description |
| Heading | 20px | 600 (semibold) | 1.2 | Quiz title on intro/taking screens, modal title ("Ссылки доступа"), section headings |
| Display | 28px | 600 (semibold) | 1.2 | Result page score ("8 из 10 (80%)"), taker name on result page |

**Additional note:** The countdown timer uses monospace digits to prevent layout shift as digits change. Apply `font-variant-numeric: tabular-nums` (Tailwind: `tabular-nums`) to the timer element.

## Surface Anatomy

### 1. Quiz Intro + Access Screen (`/q/:token`)

**Layout:** No AppHeader. Full-page centered column. Guest-only, standalone surface (focused exam flow — no owner nav).

```
page bg: #0a0a0a, min-h-screen, flex flex-col items-center justify-center, px-4 py-12
  └── card: bg-neutral-900 rounded-2xl p-8 w-full max-w-md shadow-lg
```

**Card anatomy (top to bottom):**
1. Cover image (if set): `w-full aspect-video object-cover rounded-xl mb-6`. If no cover: omit entirely (no placeholder — the card has sufficient content without it).
2. Quiz title: `text-heading` (20px/600), `text-neutral-50`, `mb-2`
3. Meta row: question count + time limit (if set) — `text-body` (14px/400), `text-neutral-400`. Example: "10 вопросов · 15 мин". If no time limit: "10 вопросов". Separator: ` · `.
4. Description (if set): `text-label` (16px/400), `text-neutral-400`, `mb-6`, `line-clamp-3`. Omit element if description is null.
5. Divider: `border-t border-neutral-800 mb-6`
6. Login form:
   - Label "Логин": `text-body` (14px/400), `text-neutral-400`, `mb-1`
   - `<Input>` — login field, `type="text"`, `autocomplete="username"`, full width, `mb-4`
   - Label "Пароль": `text-body` (14px/400), `text-neutral-400`, `mb-1`
   - `<Input>` — password field, `type="password"`, `autocomplete="current-password"`, full width, `mb-6`
7. "Начать" button: `<Button variant="default">` (orange), full width, `w-full`

**Form states:**
- Default: fields empty, button enabled
- Loading (after "Начать" click): button shows `Loader2 animate-spin` + "Начать", disabled
- Wrong credentials: `toast.error("Неверный логин или пароль.")`, form remains, fields NOT cleared
- Expired link: show `GracefulState` (see Graceful States section below), not the form
- Valid login, no questions yet: redirect to "тест пока не готов" state (D-19)

**Timer display on intro:** Time limit shown as plain text in meta row ("15 мин"), not a running countdown. The countdown only starts after "Начать".

**Re-entry routing (D-04):**
- In-progress session, time not expired → skip intro, go directly to taking screen at saved question index, timer running from server `started_at`
- In-progress session, time expired → auto-submit in store action → redirect to result
- Finished session + single-attempt → redirect to result page (no form shown)
- Finished session + multiple-attempts (`allow_retake: true`) → show intro with form again; "Начать" creates a new `quiz_session`
- No session → show intro with form

### 2. Quiz-Taking Screen (`/q/:token` — active session state)

**Layout:** No AppHeader. Full-page, `min-h-screen`, two-row grid: sticky header (auto) + scrollable body (1fr).

```
page: display grid, grid-template-rows: auto 1fr, height: 100dvh, overflow: hidden
  ├── TakingHeader (sticky, z-10)
  └── TakingBody (overflow-y: auto, overscroll-behavior: contain)
```

#### TakingHeader

`bg-neutral-900 border-b border-neutral-800 px-4 py-3 h-14 flex items-center gap-4`

**Left section (flex-1):**
- Progress label: "Вопрос X из Y" — `text-body` (14px/400), `text-neutral-400`, `mb-1`
- Progress bar: `w-full h-1 rounded-full bg-neutral-800` track; `bg-orange-500 rounded-full h-1` fill; `style="width: {percent}%"` — `transition-all duration-300`.

**Right section (shrink-0, flex items-center gap-3):**
- Timer (conditional on `time_limit_sec !== null`):
  - Normal state: `text-label` (16px/400), `text-neutral-400`, `tabular-nums`, format `MM:SS`
  - Alert state (≤20% remaining): `text-label` (16px/600), `text-red-500`, `tabular-nums`. No animation — color change only.
  - Layout: pill badge `bg-neutral-800 rounded-full px-3 py-1 flex items-center gap-1.5` + Lucide `Clock` icon (16px) + time text
- Stop button (conditional on `show_stop_button: true`): `<Button variant="ghost" size="sm">` — "Стоп" text + Lucide `StopCircle` icon (16px). No red color in default state — it's a secondary action, not destructive in appearance here.

#### TakingBody

`px-4 py-6 flex flex-col max-w-2xl mx-auto w-full`

**Question card:**
```
bg-neutral-900 rounded-2xl p-6 mb-6
  ├── question text: text-label (16px/400), text-neutral-50, mb-6
  └── answer options list: flex flex-col gap-3
```

**AnswerOptionTaking row** (reuses visual language from `AnswerOptionEditor.vue`):

`min-h-[44px] flex items-center gap-3 rounded-xl px-4 py-3 cursor-pointer transition-colors`

- Unselected: `bg-neutral-800 border border-neutral-700 hover:border-neutral-600`
- Selected: `bg-neutral-800 border border-orange-500`

Left indicator:
- Single question: circle `h-5 w-5 rounded-full border-2 shrink-0` — unselected: `border-neutral-600 bg-neutral-900`; selected: `border-orange-500 bg-orange-500` + inner white dot `h-2 w-2 rounded-full bg-white`
- Multiple question: square `h-5 w-5 rounded border-2 shrink-0` — unselected: `border-neutral-600 bg-neutral-900`; selected: `border-orange-500 bg-orange-500` + `<Check class="h-3 w-3 text-white" />`

Answer text: `text-label` (16px/400), `text-neutral-50`, `flex-1`

**Interaction:** Clicking the row selects/deselects the answer. Single-type: selecting one deselects others (radio semantics). Multiple-type: toggleable independently. Selection triggers immediate upsert via store action (TAKE-07 — no explicit save step).

**Required question blocked state (D-07):** When `is_required` and no answer selected, "Вперёд" is disabled (`disabled` attr, `opacity-50 cursor-not-allowed`). No toast — the button state is sufficient signal. A small hint appears below the options: `text-body` (14px/400) `text-neutral-400` "Выберите ответ, чтобы продолжить."

#### Navigation Footer

`pt-4 flex items-center justify-between mt-auto`

- "Назад" button (conditional on `allow_back: true` AND not on first question): `<Button variant="outline">` + Lucide `ChevronLeft` (16px). On first question: button is rendered but `disabled`.
- "Вперёд" button (not on last question): `<Button variant="outline">` + Lucide `ChevronRight` (16px). Disabled when required question unanswered.
- "Завершить" button (last question only, replaces "Вперёд"): `<Button variant="default">` (orange). Opens stop-confirmation dialog (same dialog as "Стоп", see below) — same finalization path.

When `allow_back: false`: "Назад" button is not rendered at all (not hidden, not disabled — absent).

### 3. Stop Confirmation Dialog

**Trigger:** "Стоп" button (sticky header) OR "Завершить" button (last question footer).

**Component:** `<Dialog>` (radix-vue `DialogRoot`) — same pattern as Phase 1 delete dialogs.

**Width:** `max-w-md sm:max-w-[425px]`. `bg-neutral-900 rounded-2xl p-6`.

**Anatomy:**
- Title: "Завершить тест?" — `text-heading` (20px/600), `text-neutral-50`
- Body: "Ваши ответы сохранены. Результат будет подсчитан по ответам на момент завершения." — `text-label` (16px/400), `text-neutral-400`
- Actions row (`flex gap-3 justify-end mt-6`):
  - "Отмена" — `<Button variant="outline">` — closes dialog, returns to question
  - "Завершить" — `<Button variant="destructive">` — submits session → result page

### 4. Timer-Expired Notice

**Trigger:** Client-side timer reaches 0. Auto-submit sequence begins immediately.

**Treatment:** A centered overlay notification on top of the taking screen. NOT a full-page block — the question remains visible beneath.

```
fixed inset-0 bg-black/60 flex items-center justify-center z-50
  └── card: bg-neutral-900 rounded-2xl p-8 max-w-sm text-center shadow-xl
        ├── Lucide Clock icon, 48px, text-red-500, mb-4
        ├── Heading: "Время вышло" — text-heading (20px/600), text-neutral-50, mb-2
        └── Body: "Тест отправляется автоматически..." — text-label (16px/400), text-neutral-400
              + Loader2 animate-spin ml-2 (inline)
```

No user action required. After submit completes (Edge Function returns), router pushes to result page. The overlay is not dismissible.

### 5. Result Screen (`/q/:token/result`)

**Layout:** No AppHeader. Full-page centered column. `min-h-screen flex flex-col items-center justify-center px-4 py-12`.

```
card: bg-neutral-900 rounded-2xl p-8 w-full max-w-md text-center shadow-lg
```

**Card anatomy (top to bottom):**
1. Score percentage: "80%" — `text-display` (28px/600), `text-neutral-50`, `mb-1`
2. Score fraction: "8 из 10" — `text-heading` (20px/400), `text-neutral-400`, `mb-2`
3. Taker name (from `quiz_access.label`): "Иван Иванов" — `text-label` (16px/400), `text-neutral-400`, `mb-6`
4. Divider: `border-t border-neutral-800 mb-6`
5. Neutral message: "Тест завершён. Спасибо за участие." — `text-label` (16px/400), `text-neutral-400`, `mb-8`
6. Home link: `<a href="/">` styled as `<Button variant="link">` — "Перейти на Quiz Flow" — `text-orange-500 underline-offset-4 hover:underline`

**Score rendering (D-17, D-18):** `score` from DB is `numeric`. Percentage = `Math.round((score / total_questions) * 100)`. Display: `"{percent}%"` on line 1, `"{score.toFixed(1)} из {total_questions}"` on line 2. If score is a whole number (e.g. 8.0), display as "8 из 10" (no decimal). Use `Number.isInteger(score) ? score : score.toFixed(1)`.

**No per-question breakdown** (D-11 — deferred to v2).

### 6. Graceful States

All graceful states: no AppHeader, full-page centered column, `min-h-screen flex flex-col items-center justify-center px-4`.

```
card: bg-neutral-900 rounded-2xl p-8 w-full max-w-sm text-center
  ├── Lucide icon, 48px, text-neutral-600, mb-4
  ├── Heading: text-heading (20px/600), text-neutral-50, mb-2
  └── Body: text-label (16px/400), text-neutral-400
```

| State | Icon | Heading | Body |
|-------|------|---------|------|
| No questions yet (D-19) | `FileQuestion` | "Тест пока не готов" | "Автор ещё не добавил вопросы. Попробуйте позже." |
| Invalid / expired token | `LinkOff` | "Ссылка недействительна" | "Эта ссылка устарела или не существует. Обратитесь к автору теста." |
| Wrong credentials (after retry exhaustion — not used; single attempt shows toast) | — | — | — |
| Session expired (tab closed + re-opened, JWT gone, can't resume) | `Clock` | "Сессия истекла" | "Время сессии вышло. Обратитесь к автору теста для нового доступа." |
| Already completed (single-attempt, no retake) | `CheckCircle` | "Тест уже пройден" | "Вы уже завершили этот тест. Повторное прохождение недоступно." |

**Note:** "Already completed" state routes to the result page instead when `get-quiz-result` can retrieve the existing session. The graceful state only shows when no result data is retrievable.

### 7. Access-Link Management Modal (Owner-Facing)

**Trigger:** "Ссылки доступа" button (`<Button variant="default" size="sm">` — orange) in the quiz editor header, right section. Button label: "Ссылки доступа" + Lucide `Link` icon (16px) to the left.

**Modal:** Full `<Dialog>` with overlay. Not a drawer.

```
DialogContent: bg-neutral-900 rounded-2xl p-6 w-full max-w-lg max-h-[80vh] flex flex-col
  ├── Header row: title "Ссылки доступа" (text-heading 20px/600) + close button (Lucide X, ghost)
  ├── Body (overflow-y: auto, flex-1): link list + create form
  └── (no footer — actions inline)
```

#### Create Form (top of modal body)

`bg-neutral-800 rounded-xl p-4 mb-6`

Fields (stacked vertically, `gap-3`):
1. Label "Имя тестируемого" — `text-body` (14px/400), `text-neutral-400`, `mb-1`; `<Input>` — `type="text"`, `placeholder="Например: Иван Иванов"`, full width
2. Label "Срок действия" — `text-body` (14px/400), `text-neutral-400`, `mb-1`; `<Input>` — `type="date"`, full width, optional (placeholder: "Без ограничения"). Note: `type="date"` native input — dark-themed via CSS (`color-scheme: dark` on the element).
3. "Создать ссылку" button — `<Button variant="default">` (orange), `w-full`, Lucide `Plus` icon (16px) left

**Loading state:** Button shows `Loader2 animate-spin`, disabled. "Имя тестируемого" field required (show `toast.error("Укажите имя тестируемого.")` if empty on submit attempt).

#### Post-Creation Credentials Block

Appears immediately below the create form after successful creation, **replaces** the form until dismissed or until the user creates another link. This is the ONLY moment the plaintext password is shown (D-15).

```
bg-neutral-800 border border-orange-500 rounded-xl p-4 mb-6
  ├── Heading: "Данные для доступа" — text-body (14px/600), text-neutral-50, mb-3
  ├── Credentials text block (monospace, selectable):
  │     "Ссылка: https://quizflow.ru/q/{token}"
  │     "Логин: {login}"
  │     "Пароль: {password}"
  │     text-body (14px/400), text-neutral-300, leading-relaxed
  ├── Warning: "Пароль показывается только сейчас и не может быть восстановлен."
  │     text-body (14px/400), text-amber-400, mt-2
  └── "Скопировать" button — <Button variant="default"> (orange), w-full, mt-3
        Lucide Copy icon (16px) left
        After copy: button text changes to "Скопировано ✓", text-neutral-50, green check — reverts after 2s
```

The credentials block is dismissed when the user: (a) creates another link (new block replaces it), or (b) closes the modal.

#### Link List

`flex flex-col gap-2`

Each link row: `bg-neutral-800 rounded-xl px-4 py-3 flex items-center gap-3`

**Row anatomy:**
- Taker name (label): `text-label` (16px/400), `text-neutral-50`, `flex-1`, `truncate`
- Login text: `text-body` (14px/400), `text-neutral-400`, `shrink-0`. Format: `@{login}`
- Expiry (if set): `text-body` (14px/400), `text-neutral-400`, `shrink-0`. Format: "до 31.12.2025". If no expiry: "Бессрочно", `text-neutral-600`.
- Delete button: Lucide `Trash2` (16px), `<Button variant="ghost" size="icon">`, `text-neutral-500 hover:text-red-500`. No confirmation dialog — immediate delete with `toast.success("Ссылка удалена.")`.

**Empty link list:** When no links exist yet:
```
text-center py-8
  ├── Lucide Link2Off icon, 32px, text-neutral-700, mb-3
  └── "Ссылки ещё не созданы" — text-body (14px/400), text-neutral-500
```

## Responsive Breakpoints

Guest-facing screens (intro, taking, result, graceful states) MUST be usable on mobile — takers may receive a link on their phone.

| Breakpoint | Applied To |
|------------|-----------|
| Default (mobile-first) | Single-column, `max-w-md` cards centered with `px-4` |
| sm (640px) | Taking screen: answer options maintain comfortable `min-h-[44px]` touch targets |
| md (768px) | TakingBody: `max-w-2xl mx-auto` for question card; header stays full-width |
| (no lg breakpoint changes) | Guest screens are intentionally narrow and focused |

**Owner-facing modal** (`max-w-lg`): usable from the editor which is desktop-only (≥768px). No mobile consideration needed for the modal.
